# YouTube-clone
small scale, youtube inspired video upload and sharing platform, with a node.js backend and postgreSQL database

video upload:

when a user clicks upload from the homepage it checks if there is a session to indicate logged in if there is none they are directed to login page if they are logged in they
are brought to the upload page where they can upload a file:

when clicking upload they open a file upload and can choose a mp4 to upload; the file uploader can also be triggered by a file being dropped into the drag and drop area where
the dropped files are transferred into the file upload where they are processed the same as if uploaded directly
once a file has been selected in the file uploader you can input a video title followed by clicking the upload button:

the file and its corresponding title are then append to a form data  and then sent over to the backend using xhr allowing for a percentage of completion to be displayed
during the upload as the file may take a considerable duration to be sent over; this progress percentage is then displayed onto a progress bar for user to track progress.

when received by the upload route multer stores the file to disk storage in uploads/videos where it is given a url safe base64 nanoid witch is checked for duplicates that
may cause overwriting.

a 200 status is sent back confirming upload then a title is defined using the video title sent over and a video path is defined using multers stored filename previously
generated by nanoid; a thumbnail path is also created using same nanoid config.

a new promise is created in witch ffmpeg is used to retrieve stored file via uploads/videos/ "video path" where it is then compressed to 720p along with other modifications 
(-c:v libx264", "-preset medium", "-crf 25);during the process the compressed file is being written/outputted to uploads/temp with the same file name; however once 
compression is complete and promise is resolved the compressed copy waiting in temp is renamed to uploads/videos via file system effectively overwriting the original
with the compressed copy while maintaining same file name; following this a overwriting complete message is sent.

following videos compression and overwriting a new promise is made in witch ffmpeg using the video still in uploads/videos/ "video path" to create a thumbnail from the
timestap 0% (start of video) and at 720p with the filename as previously defined thumbnail path created by nanoid in the same fashion as video path; using this thumbnail
path it is then stored in uploads/thumbnails.

once the promise is resolved and thumbnial created and stored a username is defined using currant user id found in session; this assumes a session exists as in order to
upload a login is required.

following this the username is used to make a query to the postgres database in witch the id of the username is found; this id is then used to make a additional query to
the database a row is inserted into the videos table with its (title, videopath, thumbnailpath, id) corresponding to (title, path, thumbnail, uploader_id); the video id
is serial so is added automatically in numerical order eg video id 1,2,3 ect; the video upload date is also recorded and stored by the database into the row; views is 0
by default and is only changed later when it is watched.

video retrieval:

when on the homepage videos are fetched in groups of 3; this function is called when first arriving on homepage and later when load more button is clicked;
the fetch videos function takes 2 arguments offset and limit and using those two values sends a post to the backed end where the "limit" number of video rows
are retrieved from the database starting from "offset" rows down (videos are ordered in descending order of views): furthermore the users username is also retrieved
from the row in the users table where the user id joins on uploader id of videos table (where user id = uploader id; ensuring uploaders username i sent back along
with rest of video data); this is all then sent back to the frontend.

for each row the source of the thumbnail is set to that of the received thumbnails file location (uploads/thumbnails/ "thumbnail path"); this thumbnail is then
appended inside a link with the href set to "site name"/video/ "video path"; this is then all displayed inside the video container along with the title and date
of upload and views; in addition the uploaders username is also displayed as a link with the href being the users/ "uploaders id";

after every cycle of the for each loop it adds 1 to the offset value (starts at 0) this means that it wont keep retrieving the first 3 rows in order of views
as it will start from the last video eg retrieves first 3 videos then retrieves first 3 after 3 down meaning you are actually retrieving video 4,5 and 6.

when a user clicks on the thumbnail of the video (a link) the backend video route will be triggered and whatever entered after video/ is used as the video path
as when clicking on a video it will transport you too /videos/ "video path of the video you clicked"; then too check if the video in the url is that of a real video that
has been uploaded a query is made to the database for a video with that path and if returned rows equals 0 then the backend sends back a custom 404 html page explaining
that no video has been found with this url.

if this is not the case they use the retrieved video row to find the uploaders username using uploader id then proceed to send back a different html page witch displays the
video with all the video html controls and its source is that of the video rows path.

below the video player is also views, uploaded by, and upload date as well as the videos title; furthermore a query is made to the database when this page is loaded that
updates that rows view counter by 1.

furthermore you can both in the profile viewer and the video player, subscribe to the uploaded, this is handled by first querying thr database to check if you have already subscribed to this account, this will decide both the text and action of the subscribe button, where already being subscribed will change the text to unsubscribe and the action to remove your subscription from the database, or if your not subscribed thr text will still display subscribed and if clicked will add your subscription, additionally if your are not logged in and it cannot determine whether you are already subscribed it will default the text to subscribe whereas when you click it you will be sent to the login page, additionally weather subscribed or not subscribed or not logged in, the subscriber count will be fetched from the database and displayed alongside the subscribe button.

if under both the video player or the homepage under a video thumbnail, you click thr uploader link, using a similar system to access the video player for a specific video. you will trigger the /users route while storing the user id found in the url and using it to display the name of the user along with displaying all the videos of the user and there subscriber count, functioning the same as under the video player.
